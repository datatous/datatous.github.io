## Summary
에이전트가 자기 안에서 같은 CLI 를 새로 띄우면, 환경변수 상속 때문에 "부모의 자식 세션"으로 인식돼 독립 등록되지 않는다. 사람이 직접 터미널에서 하면 되는 일이 에이전트가 하면 안 되는 전형적 원인이다. [출처: sources/016-spawning-claude-sessions-2026-08-22.md]

## Key Facts
- 세션 프로세스에 `CLAUDECODE=1`, `CLAUDE_CODE_CHILD_SESSION=1`, `CLAUDE_CODE_SESSION_ID`, 부모의 메시징 파이프가 들어 있고 **자식이 전부 상속**한다 [출처: sources/016-…]
- 띄우기 전에 그 변수들을 제거해야 새 세션이 독립적으로 등록된다 [출처: sources/016-…]
- Remote Control 은 세션이 아니라 **서버**(`claude rc`)다. 실행한 디렉터리에 세션이 최대 32개 붙는다 [출처: sources/016-…]
- 모바일 앱의 **기기 목록이 비어 있으면 서버가 안 떠 있는 것** — 세션 목록만 보면 오진한다 [출처: sources/016-…]
- 출력을 리다이렉트해 띄우면 TTY 가 없어 비대화형으로 떨어지고 죽는다 [출처: sources/016-…]
- 터미널 에뮬레이터로 감싸면 뒤에 붙인 CLI 옵션을 에뮬레이터가 파싱해 먹는다 [출처: sources/016-…]

## Details

### 왜 "사람이 하면 되는데 에이전트가 하면 안 되나"
환경변수 상속 때문이다. 사람이 새로 연 터미널에는 그 변수가 없다.
증상이 이 형태로 나타나면 **먼저 자식 프로세스의 환경을 의심한다.**

### 디버깅 순서를 뒤집을 것
프로세스 목록·파일 타임스탬프·설정 파일만 보고 원인을 세 번 추측했는데 전부 빗나갔다.
등록 파일이 없는 걸 "기동 실패"로 오판했고, 그 사이 있었던 설정 변경과 CLI 업데이트를
번갈아 의심했지만 둘 다 무관했다. 실제 답은 **모바일 앱 화면에 그대로 떠 있었다** —
기기 목록이 비어 있었다.

프로세스 밖 상태(다른 창, 다른 기기)를 추론할 때는 **사람에게 보이는 화면을 먼저 묻는다.**
추측을 쌓으면 그 위에 또 추측을 쌓게 된다.

### 증상으로 원인 좁히기

| 증상 | 먼저 의심할 것 |
|---|---|
| 사람이 열면 되는데 에이전트가 띄우면 등록이 안 된다 | 환경변수 상속 (부모 세션 표식) |
| 프로세스는 살아 있는데 아무 데도 안 잡힌다 | 서버가 안 떠 있음 / 자식으로 물림 |
| 띄우자마자 죽는다 | TTY 없음 — 비대화형으로 떨어짐 |
| 프로세스 자체가 생기지 않는다 | 터미널 래퍼가 인자를 먹음 |
| 원격 목록에 세션이 하나도 없다 | 기기(서버) 미등록 — 세션 문제가 아님 |

### 확인 순서

1. **사람에게 보이는 화면**부터 묻는다 (앱 목록, 터미널 창에 뜬 문구)
2. 자식 프로세스의 **환경변수**를 덤프해 부모 표식이 섞였는지 본다
3. 프로세스가 살아 있는지, CPU 를 쓰는지 본다 — 살아 있는데 유휴면 대기 중일 수 있다
4. 파일·타임스탬프는 **마지막**에 본다. 그 신호는 다른 이유로도 생기고 사라진다

3·4를 먼저 보면 "등록 파일이 없다 → 기동 실패"처럼 그럴듯하지만 틀린 결론에 쉽게 도달한다.
