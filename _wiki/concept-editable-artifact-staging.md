## Summary
로컬 파일이 상태의 단일 원본인데 그 상태를 웹/폰에서 고치고 싶을 때의 구조. 발행 페이지는 로컬 파일에 쓸 수 없으므로, 페이지를 **두 번째 원본이 아니라 대기함**으로 만들고 로컬 스크립트가 되돌려 쓴다. [출처: sources/015-editable-artifact-staging-2026-08-21.md]

## Key Facts
- 아티팩트 `artifact` capability(live doc)에서 저장되는 것은 **뷰어의 제스처가 DOM 을 바꾼 결과**뿐이다. 스크립트가 로드 시 그린 것은 문서가 아니다 [출처: sources/015-…]
- 따라서 내용은 **HTML 로 서빙**해야 하고, 렌더는 클라이언트 JS 가 아니라 생성 스크립트가 맡는다 [출처: sources/015-…]
- 필터·정렬 같은 뷰어별 상태는 `data-local-*` / `<artifact-local>` 로 분리한다. 일반 class 로 숨기면 그 숨김이 저장돼 모두에게 적용된다 [출처: sources/015-…]
- 발행된 아티팩트를 가져오면 **렌더된 텍스트가 아니라 원본 HTML** 이 온다. 대기 항목 파서는 `data-*` 를 직접 읽는 쪽이 정확하다 [출처: sources/015-…]
- YAML 을 파싱→덤프하면 주석이 날아간다. 수술적 라인 치환을 쓰되 **블록 경계를 캐시하지 말 것** [출처: sources/015-…]

## Details

### 왜 페이지를 SSOT로 삼으면 안 되나
웹에서 누른 변경을 곧바로 상태로 취급하면 원본이 둘이 된다. 둘이 되면 한쪽이 반드시 낡는다.
페이지는 **변경을 예약만** 하고, 기록은 원본을 쥔 쪽에서 한다.

### 왕복 절차
1. 페이지에 "미반영 변경" 목록을 두고, 버튼·인라인 편집이 그 목록에 한 줄씩 쌓는다
2. 각 줄에 id 를 `data-*` 로 박고, 사람이 읽는 텍스트(`완료 · <id> · <제목>`)도 함께 둔다
3. 로컬 스크립트가 가져온 HTML 에서 `data-*` 를 읽어 원본 파일에 기록 (평문은 폴백)
4. 재생성·재발행 → 대기 목록이 비워진 채 나간다

**대가**: 반영이 한 박자 늦다. **얻는 것**: 원본이 하나로 유지된다.

### 구조화 파일 수술적 편집
주석에 그 파일의 운용 규칙이 적혀 있는 경우(설정·레지스터류) 라운드트립 덤프는 쓸 수 없다.
항목 블록의 시작/끝을 찾아 해당 필드 줄만 교체한다.

⚠️ 줄을 지우거나 넣으면 뒤쪽 인덱스가 전부 밀린다. **매 편집마다 블록 경계를 다시 계산**해야 한다.
캐시된 인덱스로 접근하면 예외로 죽거나, 더 나쁘게는 엉뚱한 항목을 고친다.

### 의존 관계는 id 로 적는다
"막힘: X 완료 후"라는 문장은 사람은 읽지만 계산할 수 없다. 같은 뜻을 id 배열로 병기해야
"이거 하나 풀면 몇 건이 열리나"를 셀 수 있다.

- 선행조건이 여럿인 항목은 **AND 게이트** — 하나를 풀어도 열리지 않는다.
  해제 건수는 직접 간선이 아니라 연쇄로 세되, 선행조건이 **전부** 사라진 항목만 해제로 친다
- 외부 요인으로 막힌 것은 **빈 배열로 명시** — 키를 빼면 "적는 걸 잊은 것"과 구분되지 않는다
- 검증기에서 "문장은 있는데 id 없음" / "없는 id 참조"를 잡아야 간선이 조용히 사라지지 않는다
